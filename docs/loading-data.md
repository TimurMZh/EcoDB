# Загрузка данных

Как поместить новый лабораторный Excel или PDF либо новый период почасовых данных автостанций Оскемена в `eco_monitoring`.

Загрузчики не просматривают папку. Каждый открывает один фиксированный путь. Файл, сохранённый под другим именем, пропускается.

Команды запускайте из папки проекта. База уже должна работать, схема — быть применена один раз (`sql\apply.ps1` на Windows, `./sql/apply.sh` в bash). Подключение по умолчанию: хост `localhost`, порт `5432`, база `eco_monitoring`. Переопределение: `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`. На Windows в командах ниже замените `python3` на `python`.

На сервере с ролями из `docs/roles.md` команды `air`, `water` и `phase4.py` выполняет `eco_etl`. Команду `seed` выполняет учётная запись администратора. `python3 etl/phase2.py` и `python3 etl/phase3.py` без аргумента сначала запускают `seed`, и под `eco_etl` это завершается ошибкой. Указывайте `air` или `water` явно.

Пакеты Python перечислены в `etl/requirements.txt`.

## Лабораторные файлы

Новый файл сохраняйте в `DB_input/` под именем из левого столбца.

| Новый файл | Сохранить как | Команда |
|---|---|---|
| Excel воздуха | `DB_input/Результаты мониторинга воздуха.xlsx` | `python3 etl/phase2.py air` |
| Excel поверхностных вод | `DB_input/Результаты мониторинга поверхностных вод.xlsx` | `python3 etl/phase3.py water` |
| Excel подземных вод | `DB_input/Результаты мониторинга подземных вод.xlsx` | `python3 etl/phase3.py water` |
| PDF-протокол | `DB_input/Результаты мониторинга.pdf` | `python3 etl/phase3.py water` |
| Новые точки, написания показателей или нормативы | один файл `DB_input/Ecology_DB_general….xlsx` | `python3 etl/phase2.py seed` до загрузки |

Старую копию оставляйте только после переименования. `Результаты мониторинга воздуха_2025.xlsx` — архив. Загружается файл с официальным именем.

В `DB_input/` должен лежать один файл `Ecology_DB_general*.xlsx`. Шаг `seed` открывает первое совпадение этого шаблона.

Официальный файл должен содержать все периоды, которые нужно сохранить:

- `python3 etl/phase2.py air` удаляет имеющиеся лабораторные результаты воздуха по Оскемену и загружает текущую книгу (партия `AIR_PILOT`).
- `python3 etl/phase3.py water` удаляет имеющиеся результаты поверхностных и подземных вод и загружает обе водные книги вместе с PDF. Все три файла должны быть в `DB_input/`, даже если изменился только один. Партии: `WATER_SURFACE_2025`, `WATER_GROUND_2025`, `WATER_WELLS_PDF`.

Книга или PDF только с новым кварталом или годом убирает более ранние измерения из базы. Переименованный архив на диске их не сохраняет.

После загрузки:

```bash
python3 etl/phase4.py
```

Команда присваивает коды QC и перезаписывает `docs/qa_phase4_report.md`. Коды `D` и `R` не попадают в `eco.vw_latest_results`.

### Что делает PDF

`Результаты мониторинга.pdf` — это не вторая копия измерений из Excel.

- `phase3.py water` читает таблицу 9 на страницах 5–6 и загружает именные скважины (`ФС-1`, `ФС-4`, `ФС-5`, `НС-2`). В PDF нет даты отбора, поэтому каждая строка скважины записывается как 2025-01-01 и помечается `date_assumed`.
- `phase4.py` читает тот же PDF ещё раз. Страницы 1–4 сравниваются с результатами воздуха из Excel. Страницы 5–6 сравниваются со скважинами. Совпадение получает код QC `A`. Отличающееся значение скважины получает `R`.

Измерения воздуха по-прежнему берутся только из Excel воздуха. Если изменилась эта книга, запустите `python3 etl/phase2.py air`. Если изменились водные файлы или PDF — `phase3.py water`. Затем `phase4.py`.

### Строки, которые не загрузились

Неизвестные точки, названия показателей, лаборатории и пустые значения остаются в `eco.staging_lab_import`: `processed_at` пустой, причина — в `process_error`. В `eco.results` они не записываются.

```sql
SELECT batch_code, process_error, count(*)
FROM eco.staging_lab_import
GROUP BY 1, 2
ORDER BY 1, 3 DESC;
```

Если в новом файле точка или написание показателя ещё нет в справочниках, выполните `python3 etl/phase2.py seed` (учётная запись администратора) и загрузите снова.

Файл с другими столбцами или страницами PDF этими командами не импортируется. Для него нужен свой читатель: он вставляет строки в `eco.staging_lab_import` и вызывает `eco.fn_process_staging_import` с новым `batch_code`. Контракт строки описан в `etl/load_air.py` и `etl/load_water.py`.

## Почасовые данные автостанций Оскемена

Файлы автостанций в `DB_input/` не кладутся. Сначала получите и соберите их, затем загрузите:

```bash
python dataset/fetch_oskemen_raw.py --parameters pm25 pm10 so2 no2 no co h2s o3 pmtot
python dataset/build_oskemen_stations.py
python etl/load_oskemen_stations.py --since 2026-10-01
```

`--since` заменяет почасовые строки станций и метеорологию начиная с этого времени UTC и оставляет более ранние часы на месте. Без `--since` вся история станций перезагружается из `dataset/Oskemen/`. Этот путь не использует `phase4.py`.
