# Сдача: ArcGIS и эксплуатация

Инструкция к фазе 5. Регистрация слоёв выполняется в ArcGIS Enterprise заказчика. В этом репозитории проверяется контракт представлений и время ответа.

Проверка на стенде:

```bash
./sql/apply.sh
psql -h localhost -U eco -d eco_monitoring -v ON_ERROR_STOP=1 -f sql/verify_phase5.sql
```

## Что передаётся

| Материал | Где |
|---|---|
| DDL схемы, с нуля | `sql/migrations/001` … `010`, запуск `sql/apply.sh` |
| Загрузка воздуха, воды, QA/QC | `etl/phase2.py`, `etl/phase3.py`, `etl/phase4.py` |
| Акт QA/QC и объёмы | `docs/qa_phase4_report.md` |
| Перечень проверок QA/QC | `docs/qaqc-checks.md` |
| Схема | `docs/er-diagram.md` |
| Требования к серверу | `docs/server-requirements.md` |
| Эта инструкция | `docs/ops-handover.md` |

Повторный запуск миграций пропускает уже применённые версии. Полный сброс схемы: `./sql/apply.sh --reset`, затем снова фазы 2–4.

## Подключение ArcGIS

Учётная запись только на чтение (миграция `010`):

| | |
|---|---|
| Сервер | хост PostgreSQL, порт `5432` |
| База | `eco_monitoring` |
| Пользователь | `eco_gis` |
| Пароль стенда | `eco_gis` |

Пароль стенда нужно сменить до промышленной публикации. Роль `eco_gis` имеет только `SELECT` по схеме `eco`. Загрузку данных выполняет пользователь `eco`.

Четыре представления регистрируются как Query Layer. У каждого есть уникальное поле `objectid` (bigint) и столбец `geom` типа Point, EPSG:4326. `NULL` в `geom` допустим.

| Представление | Строка | Поле уникальности |
|---|---|---|
| `eco.vw_results_flat` | один результат | `objectid` = `result_id` |
| `eco.vw_exceedances_summary` | результат × норматив | `objectid` = `exceedance_id` |
| `eco.vw_latest_results` | последний результат пары (точка, показатель) | `objectid` = `result_id` |
| `eco.vw_water_levels` | замер уровня воды | `objectid` = `level_id` |

`vw_latest_results` не содержит коды QC `D` и `R`. Сейчас это 720 строк HCN, у которых пустая ячейка Excel была записана как «не обн.».

Порядок в ArcGIS Pro:

1. Новое подключение к базе: PostgreSQL, пользователь `eco_gis`.
2. Добавить Query Layer. Запрос: `SELECT * FROM eco.vw_results_flat` (и то же для остальных трёх представлений).
3. Уникальное поле: `objectid`. Проверить слой.
4. Если система координат не подхватилась из PostGIS, указать WGS 1984 (EPSG:4326).
5. Опубликовать слой на ArcGIS Enterprise (карта, Feature Layer или Query Layer — по принятой у заказчика схеме портала).

`objectid` имеет тип bigint. ArcGIS Pro 2.9 и Enterprise 10.9.1 понимают 64-битный идентификатор. На текущих объёмах значения помещаются и в 32-битный integer.

Пока у всех точек `geom` пустой, слой регистрируется, но на карте не рисуется. Координаты появятся после каталога точек (долгота, широта, код точки) и обновления `eco.monitoring_points.geom`. Повторно публиковать определение слоя не нужно: геометрия читается из той же вьюхи.

`vw_water_levels` пустая: замеров уровня в исходных файлах нет.

## Дозагрузка новой партии

1. Положить файл в `DB_input` (или указать путь в загрузчике).
2. Если появились новые точки, лаборатории или написания показателей — дополнить справочники (`python3 etl/phase2.py seed`) и синонимы в `eco.parameter_aliases` / `eco.point_aliases`.
3. Загрузить сырые строки в `eco.staging_lab_import` со своим `batch_code`. Существующие загрузчики:

```bash
python3 etl/phase2.py air    # AIR_PILOT, файл воздуха
python3 etl/phase3.py water  # три водных партии
```

Для нового файла нужна своя функция чтения. Контракт строки staging описан в `etl/load_air.py` и `etl/load_water.py`: код точки, название или код показателя, дата, сырой текст результата, `batch_code`. Преобразования делаются не при вставке в staging, а функцией:

```sql
SELECT * FROM eco.fn_process_staging_import('НОВЫЙ_КОД_ПАРТИИ');
```

Функция идемпотентна по паре (проба, показатель): повтор обновляет `results`. Неразобранные строки остаются с `processed_at IS NULL` и текстом в `process_error`.

4. Пересчитать QC и акт:

```bash
python3 etl/phase4.py
```

## Пересчёт превышений

Триггер `trg_check_exceedances` срабатывает при INSERT и UPDATE `eco.results`. После смены строк в `eco.guideline_values` нужен полный проход:

```sql
SELECT eco.fn_recalc_all_exceedances();
```

Повторный запуск не создаёт дублей: уникальность `(result_id, gv_id)`. Если на дату и среду нет норматива, превышение не пишется. Для подземных вод и скважин PDF норматив в источнике указан как «Не норм-ся», поэтому превышений по ним нет.

## Ограничения текущей поставки

- Пяти лет лабораторных выгрузок воды нет. В базе отчётные таблицы 2025 года и скважины из PDF.
- Координат точек нет.
- Почвы и растительности в исходных файлах нет.
- `GW-1`…`GW-4` повторяют значения `SW-1`…`SW-4` за 1 квартал 2025. Точки не слиты.
- Регистрация в ArcGIS Enterprise на этом стенде не выполнялась: среды Enterprise здесь нет. Контракт вьюх и лимит 3 секунды проверяет `sql/verify_phase5.sql` на объёме загруженных данных (объект `OSK`, 2020–2025).
